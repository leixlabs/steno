# docs

四类纸，过期速度完全不同。引用某一篇之前先看它属于哪一类——把决策记录当成现状，
是这套文档最容易造成的误读。

| 目录 | 里面是什么 | 该不该照着做 |
|---|---|---|
| `spec/` | 动手前写的规格书与任务拆分（v0.6） | **不该**。代码已经偏离，它只用来解释代码注释里的 `§4.3`、`§11`、`T8.6` 指的是什么 |
| `decisions/` | 带日期的决策与调查记录 | **不该当成现状**。它们解释「为什么当时这么选」，代码与它冲突时代码是对的 |
| `operations/` | 现在还要照着执行的东西 | **该**。部署、排障、量指标 |
| `verification/` | 还没实测的验收模板 | 只有把「待实测」填成真实数字之后才算文档 |

## 约定

- **命名**：`decisions/` 与 `operations/` 的文件名以 `YYYY-MM-DD-` 开头，目录里按时间自然排序；`spec/`、`verification/` 不带日期，因为它们不是某个时刻的快照。
- **代码是真相**：记录和代码冲突时改记录，不要为了符合旧文档去改代码。已经过时的记录在开头加一行
  `> **更正（日期）**：…`，不要重写历史。
- **不加空文档**：宁可让某件事没有文档，也不写一篇读起来像完成了、实际全是占位符的文件。
  现在挂着「待实测」的两篇是例外，它们是明确标记的待办清单。
