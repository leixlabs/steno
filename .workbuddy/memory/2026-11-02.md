## audio.cpp / Qwen3-ASR 识别后端（`--backend audiocpp`）

- 新增 `apple-stt-sidecar/Sources/AudioCPPBackend.swift`：一个长驻 `audiocpp` 子进程，stdin 喂 16 kHz mono s16le，stdout 按行收文本。`Backend.swift` 去掉 `BackendError.notCompiledIn`，`make/probe/install` 带 `AudioCPPConfig`；`Options.swift` 加 `--model / --chunk-seconds / --audiocpp-bin / --model-package` 与四条 parse 期拒绝；`PipelineConfig` 透传。
- 模型目录（本机）：`/Users/lei/dev/projects/2601-monosub/models/asr/qwen3_asr`（0.6B q8）。仓库里不再放 `models/`，已加 `.gitignore`。
- dev 用法：`STENO_STT_BACKEND=audiocpp STENO_STT_MODEL=… [STENO_STT_CHUNK=8] tools/dev.sh`。

踩到的坑（都写进了 `docs/decisions/2026-11-02-audiocpp-qwen3-asr.md`）：

1. `partial_text=` 是**一窗的定稿**，不是 partial → 转成 `final`，`partials: false`。
2. `text_output=` 是整场拼接 → 必须丢弃，否则整夜写两遍。
3. 静音窗**什么都不打印** → 窗口编号只能自己记（`windowIndex`），不能数行。
4. `finish()` 必须先排空 writer 再关 stdin，否则 `--mode file` 丢掉绝大部分音频（第一版只出 1 个窗口）。
5. 服务端等的 launcher 必须**立刻返回**（`Command::status()`），测试 wrapper 用 `exec` 会永远卡在 starting。
6. `--audio-chunk-mode vad` 在流式下被拒（"requires offline --task vad"），只能用 `fixed`。
7. 引擎对 `--language xx-YY` 照单全收 → 语言码必须自己按 family 列表校验。

实测：5 s 窗口、延迟 ~1.3 s、RTF ≈ 0.26；170 s 压测 34 个 final、RSS 平稳 1.38 GB；经真实 server + UDP 回放，DB 里 3 条 `engine=audiocpp-qwen3-asr`。

## 事故与修正：wrapper 的模型路径不能靠 sed 替换

把 `--model` 用 `sed` 塞进 wrapper → 每次不带环境变量的重装（`refresh-all.sh` 就是）都会把它替换成空串，wrapper 在 `-z "$MODEL"` 处 exit 2，服务端只报 `launcher exited with exit status: 2`。改成 `$PREFIX/lib/steno-stt-sidecar-audiocpp.conf`：只有显式给 `STENO_STT_MODEL` 才写，否则保留；wrapper 先 source conf 再看环境变量。已回归验证「无参重装后 conf 不变、wrapper 照常启动」。

## 床边 Pi 换麦克风（Razer Seiren → 廉价 USB Audio）

- 现象：旧 Razer 拔出后，`steno-node` 进程仍holding 已消失的 PCM 句柄，`systemctl` 显示 active 但实际不出声；19:37 被重启后立刻进入 `DeviceNotFound` 崩溃循环，并打满 systemd start limit（`start request repeated too quickly`）。
- 新设备枚举名（cpal 用 `Display` = ALSA 描述）：`USB Audio, USB Audio`。`lsusb` 为 `1620:0b21`，硬件只支持 **48 kHz / 2ch S16_LE**（`device_channels = 1` 仍可用，协商走 default config 再由 WireConverter 降到 16 kHz mono）。
- 注意：`alsa_device = ""` 在这台板上**不可用**——cpal 会枚举出 17 个条目（`null` + 同一张卡的 16 个别名），必然 `MultipleDevices`。必须显式写描述名。
- 修复：`/etc/steno-monitor/node.toml` 改 `alsa_device`，`systemctl reset-failed steno-node` 后 `start`（先 `reset-failed`，否则启动限流仍拒绝）。备份 `node.toml.bak-20261102`。
- 验证：`arecord -D plughw:1,0 -r 48000 -c 2` 6.000 s 精确 288000 帧（时钟准），双声道内容一致（单声道复制）；服务端 `/status` 显示 `node_connected=true`、`microphone.state=ok`、xrun/lost/clipped 全 0，分段正常落盘。
- 遗留：`[stt]` 仍报 launcher 退出 2（`~/.local/bin/steno-stt-sidecar-audiocpp` 未装好），与麦克风无关。

## 节点开机自启改为默认

- 起因：20:27 Pi 重启过一次，`steno-node` 因为 `disabled` 没起来——正好实证了"今晚在跑、断电就没声音"。
- `tools/deploy-node.sh`：`DO_ENABLE` 默认 1，新增 `--no-enable`（`--enable` 保留为等义词）；**不再用 `enable --now`**，改成 `enable` + `restart` 两步——`--now` 只启动没在跑的单元，已在跑的节点会继续执行刚被替换的旧二进制。部署末尾回读 `systemctl is-enabled`，不是 enabled 就 `die`。
- `tools/refresh-all.sh`：新增 `NODE_ENABLE=1` 与 `--no-enable-node`；step 6 显式拼 `--enable` / `--no-enable`（不再靠 deploy 的默认，也不再用 `${PI_ARGS[@]+...}` 那个空数组 idiom——改成先拷进 `NODE_ARGS`）。
- 文档同步：`AGENTS.md`（含"换麦克风会改描述名→DeviceNotFound"）、`tools/README.md`、`deployment/README.md`。
- 验证：4 种参数组合的 dry-run 输出都正确；真跑一次 `deploy-node.sh --no-build` → `enabled at boot: enabled` + active + 电平 -31.5 dBFS（设备侧）/ -54.6（服务端）；节点重连 `node_connected=true`。
